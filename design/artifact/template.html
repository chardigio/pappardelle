Run-through findings

  1. PR !58 bugIn the blink's "on" phase OpenTUI emits the row as inverse with the same palette slot for foreground and background (7;38;5;4;48;5;4), so blocked rows become a solid bar with no text half the time. This affects any colored inverse span, not just the rail.
  2. PR !58 bugEmoji with a variation selector (🛠️, ❤️) measure two cells in string-width and one in OpenTUI's layout, so a row with one as its profile emoji overflows by a cell. This is the emoji-row-width ❤️ test that fails on macOS.
  3. The agent's state is what you act on, and it is a single glyph. The issue key next to it is colored by the tracker's workflow state, so each row carries two unrelated color systems and the louder one is the less urgent.
  4. Selection inverts only the key and title, so its block is as wide as the text. Selected rows get a ragged edge and leave the emoji, status and PR icons outside the highlight.
  5. Agents already report progress, a message and a title over OSC 7501, and Claude's hooks report the running tool. The rail shows none of it.
  6. At 23 to 28 columns a one-line title gets 8 to 14 cells, and the team prefix repeats on every row.
  7. The second header row is reserved for short yellow status messages and is empty most of the time.
  8. Every confirmation uses the red double border, including updating Pappardelle and rewriting config.
  9. Pending rows color the key with ANSI white, which most light themes render as light grey. On Solarized Dark, ANSI gray (slot 8) is the background color itself, so anything styled gray disappears.
  10. The new-space instructions say STA-123 whatever the repo's prefix is.
  11. The help legend lists "working" without its glyph.
  12. The tmux chrome is generic: colour238 borders, a cyan active border, pane titles set but never shown, and a bare No session for tra-l38 in the agent pane.
Are animations a thing in TUIs?

Yes, within a cell grid

A terminal draws whole character cells, so motion comes from swapping glyphs, stepping through block characters and, with truecolor, easing colors. OpenTUI 0.8.2 provides a shared animation clock (useAnimationTick), a timeline with 16 easings, and opacity and translate on any box. Since 0.8.0 it repaints only rows that changed, and when nothing animates it renders nothing, so an idle rail costs no frames.

Two limits shape every direction below. In 16 colors there is no fade, only normal, bold and dim, so motion has to come from glyphs. And inside tmux, OpenTUI only uses truecolor when COLORTERM=truecolor reaches it; otherwise colors are rounded to the 256-color palette.

Glyph cycling

Swap one character on a timer. This is the cheapest motion, since one cell repaints per tick and every spinner on screen can share one clock.

Sub-cell progress

Eighth blocks give a bar eight steps per cell, so a 24-cell bar moves in 192 steps instead of 24. It's plain text and works in 16 colors.

Half-row glide

A cell holds two half-blocks (▀ ▄). A marker drawn from them can sit between rows mid-move, which halves each jump. Left: whole-row jumps.

Color fade

Truecolor can ease a color every frame. 16 colors can only step between normal and dim, so a design has to read without the fade. Switch Colors to compare.

Shimmer

A band of brighter cells sweeps across text when something new arrives. Truecolor brightens the band; 16 colors bolds it.

Slide in

Text can't move less than a cell, but easing out over 300 ms makes the cell steps read as one movement. Linear motion looks mechanical next to it.

Scrim

A scrim dims what sits behind a dialog. OpenTUI blends cells by opacity in truecolor; in 16 colors it uses the dim attribute.

Typewriter

Reveals text a few characters per frame. It suits something arriving, like a ticket printing, and gets tiring on anything you read often.

Direction 1

Quiet craft

Hierarchy comes from weight and spacing, and color is reserved for agent state. The rail is calm at rest and moves only when something changes.

  • Status glyphs are one geometric family: ◴ working, ○ idle, ● done, ◆ needs you, ✕ error, ◌ compacting.
  • Keys are plain text. The selected row's tracker state moves into the rule under the header, so a row never carries two palettes.
  • Selection is a full-height bar ▌; in truecolor the whole row gets a faint tint.
  • When an agent starts needing you, its row pulses three times and then holds a steady accent. The header keeps the count.
  • Borders are drawn with the dim attribute, which recedes on every theme. ANSI gray would vanish on Solarized Dark.

Direction 2

Kitchen pass

The rail is the pass in a restaurant kitchen. Workspaces are tickets, grouped by station, and the agents are line cooks. It builds on the name and on sous-chef, which already exists.

  • Tickets group by what they need from you: calling, firing, on the pass, 86, cold. This reorders the rail, so it is a behavior change to try before adopting.
  • Ticket numbers drop the repeated team prefix: PAP-412 reads #412, which gives the title four more cells.
  • Kitchen words are short and always paired with their plain meaning in help: FIRE working, HOLD idle, CHEF? question, SIGN permission, PLATED done, BURNT error, REDUCE compacting.
  • Every ticket shows how long it has been in its state. That needs the new stateSince field.
  • Dialogs are tickets with a perforated bottom edge. Closing a space voids a ticket.

Direction 3

Living rail

Motion shows what agents are doing. Rows with a live agent move, new output shimmers, progress fills its row and the selection glides. Every animation is tied to an event or a live agent.

  • The second header row becomes a ticker showing the newest thing any agent said, so a message from a row scrolled out of view still reaches you.
  • OSC progress fills the row from the left: a tint in truecolor, an underline in 16 colors.
  • Needs-you rows pulse continuously, eased in truecolor and as a ring ◎◉ in 16 colors. Nothing blinks on and off.
  • The selection pill moves at half-row resolution, so a move reads as one motion.
  • Dialogs grow open in 150 ms. Confirming shows a progress sweep while close hooks run, instead of a frozen dialog.

Direction 4

Mission control

The rail as an instrument panel. Every row carries a readout, the header reads the whole fleet at once, and an agent that needs you raises a master caution. It shows the most data per cell of the four directions and moves the least.

  • Four signal colors, used the same way everywhere: cyan for live agents, amber for caution (an agent needs you), red for a failure, green for done.
  • The header is a fleet readout: counts by state and a bar split by how many agents are in each.
  • Every row ends in a telemetry column: OSC progress, the running tool, or a short state code (RUN, ASK, PERM, ERR).
  • Rows with telemetry carry gauges under them: a progress bar, the agent's message and time in state.
  • When an agent starts needing you, the header becomes MASTER CAUTION and flashes for 2.4 s, then the amber count stays.
  • On narrow rails the title goes before the pipeline glyph and the readout, the one exception to the shared drop order. Conflicts (↯) and unresolved comments (✎) sit next to the pipeline glyph.

Recommendation

Build Quiet craft as the base. It fixes the most findings, reads well on every theme including 16-color Solarized, and costs nothing at rest. Then add three pieces of Living rail where motion carries information: the progress fill, the shimmer and header ticker for new messages, and the eased needs-you pulse in place of the blink. Keep Kitchen pass's ticket numbers (#412) as an option for narrow rails, and try its grouping by station separately, since it changes where rows sit. If detail lines make the rail too tall, Mission control's readout column (40%, BASH, ASK) puts the same information on the row itself.

Implementation notes

What the follow-up touches

  1. Fix the two PR !58 bugs first: colored inverse spans (blink rows) and VS16 emoji widths. Both affect today's rail whatever direction is chosen.
  2. source/tui-style.ts gains design tokens with a 16-color value and per-theme truecolor values, picked from renderer.capabilities.rgb and renderer.themeMode (OSC 11). Nothing styles with ANSI gray.
  3. SpaceListItem.tsx and row-highlight.ts are rewritten around a row model like design/kit/row.ts, keeping list-view-sizing.ts, truncate-to-width.ts and the emoji helpers, which the prototypes already reuse.
  4. animation-clock.ts moves to useAnimationTick, with the rail asking for a frame rate only while something moves, the way each direction's fps() does.
  5. OSC progress and msg are already parsed into ProgramStatusInfo; they only need rendering. "Time in state" needs a stateSince set when the status changes.
  6. The tmux status line and border colors read user options (@pappardelle_summary and similar) that the rail sets when the fleet changes, so tmux never shells out to draw them.
  7. The new-space instructions read the configured team prefix.
  8. Rails can be dragged down to 15 columns, so every direction follows one rule: time in state, then the comment count, give way until the title has 6 cells. Pipeline and PR glyphs carry failures, so they go only when not even a … title would fit, so widening the rail never hides one. Mission control is the exception: its title goes before the pipeline glyph and readout. Set Rail to 15 in the toolbar to see it.
  9. Every row an agent is reporting on shows its detail line, selected or not, so moving the selection never reflows the list. The cost is a taller rail when many agents are talking.
  10. The dialog mockups are drawn at one size each. The real dialogs need a minimum size, or a compact layout below it, that truncates with … and keeps the input line and cursor.
